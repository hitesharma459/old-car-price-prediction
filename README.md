# CarWorth - Old Car Price Prediction

An end-to-end machine-learning web application that estimates the resale price of a used car.
React + Vite + Tailwind frontend, FastAPI backend, scikit-learn model trained on the supplied
`car_price.csv`, SQLite (SQLAlchemy) for prediction history.

> Estimates are indicative. They are **not** guaranteed market prices.

## Dataset

`data/car_price.csv`: 5,512 rows, 10 columns (see `data/README.md`). Text fields such as
`"10.03 Lakh"`, `"86,226 kms"` and `"1956 cc"` are parsed into numbers.

- Missing values: none. Exact duplicates: **76** removed.
- **12** rows dropped because the engine size was recorded as `0 cc` (a missing value).
- Outliers (IQR rule): price 659, km 111, engine 54.
  They are real cars (luxury models, very high mileage) so they are **kept**; training on log(price) limits their pull.
- Final clean dataset: **5,424** rows.
- `brand` and `model` are derived from `car_name` (e.g. "Land Rover", "Swift Dzire", "5 Series").
- The dataset has no mileage (kmpl), power or location columns, so the app does not ask for them.
- Data caveat: some electric cars carry meaningless engine sizes (e.g. a Nexon EV with "2993 cc"); only 14 electric rows exist.

## ML workflow

1. Parse and clean (above) -> `data/processed/car_price_clean.csv`.
2. EDA figures -> `backend/artifacts/eda/`; notebook in `notebooks/eda.ipynb`.
3. 80/20 train/test split (`random_state=42`).
4. One scikit-learn `Pipeline`: `FeatureBuilder` (age, log-km, km per year; brands with <5 training rows pooled as "Other",
   learned on training data only) -> `StandardScaler` + `OneHotEncoder` -> regressor wrapped to train on `log1p(price)`.
5. Five algorithms compared. Tree models and Gradient Boosting are tuned with `RandomizedSearchCV` (5 candidates, 3-fold CV, training split only).
6. Selection: lowest 3-fold cross-validated MAE in rupees on the training split. The test set is never used to choose.
7. Deployed model is refit on all cleaned rows and saved with Joblib. Reported test metrics come from the 80/20 split before that refit.

XGBoost was not used (not installed in the training environment; the five scikit-learn models were enough).

### Evaluation results (held-out test set of 1085 cars)

| Model | CV MAE | CV R² (log price) | Test R² | Test MAE | Test MSE | Test RMSE |
|---|---|---|---|---|---|---|
| Linear Regression | ₹209,432 | 0.948 | 0.910 | ₹176,709 | 2.733e+11 | ₹522,789 |
| Decision Tree | ₹277,134 | 0.870 | 0.915 | ₹231,724 | 2.583e+11 | ₹508,213 |
| Random Forest | ₹217,619 | 0.927 | 0.955 | ₹165,004 | 1.362e+11 | ₹369,020 |
| Extra Trees **(selected)** | ₹152,360 | 0.942 | 0.966 | ₹130,301 | 1.046e+11 | ₹323,491 |
| Gradient Boosting | ₹229,249 | 0.936 | 0.903 | ₹205,266 | 2.960e+11 | ₹544,054 |

Selected model: **Extra Trees** - R² 0.966, MAE ₹130,301, RMSE ₹323,491, MAPE 17.5%.

Honest notes:
- Errors are larger in absolute rupees for luxury cars. The range shown with each estimate is the middle 80% of
  relative errors on the test set (about -24% to +31%), not a guarantee.
- The deployed model has seen every row of the dataset, so predicting a car that exactly matches a dataset listing returns
  roughly that listing's price. Use the test metrics above as the real performance indicator.
- The API only prices brand/model/fuel/transmission combinations that exist in the data (for example a manual BMW 5 Series is rejected).

## Setup

Requirements: Python 3.11+ (developed on 3.12) and Node 18+.

### Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python -m app.database.init_db                          # optional: tables are also created on startup
uvicorn app.main:app --reload --port 8000
```

Swagger UI: http://localhost:8000/docs

### Retrain the model (optional; artifacts are already included)

```bash
cd backend
python -m ml.train        # ~4 minutes on one CPU core
```

### Frontend

```bash
cd frontend
npm install
cp .env.example .env      # VITE_API_URL=http://localhost:8000
npm run dev               # http://localhost:5173
```

### Tests

```bash
cd backend
pytest
```

```bash
  "fuel_type": "Petrol", "transmission": "Manual", "ownership": 1, "engine_cc": 1197, "seats": 5 }'
```

Invalid input returns `422` with a readable `detail`; missing model files return `503`.

## Deployment

**Backend on Render**
1. Push the repository to GitHub (the 22 MB model file in `backend/artifacts/` is committed, so no training is needed on the server).
2. In Render choose *New -> Blueprint* and select the repo; `render.yaml` configures the service.
   SQLite lives on a persistent disk at `/data` (paid plan). For the free tier, create a Render PostgreSQL database and set
   `DATABASE_URL` to its URL instead; the code supports both.
3. Set `CORS_ORIGINS` to your Vercel URL (comma-separated for several).

**Frontend on Vercel**
1. Import the repo, set *Root Directory* to `frontend` (framework: Vite).
2. Add environment variable `VITE_API_URL=https://<your-render-service>.onrender.com`.
3. `vercel.json` already rewrites all routes to `index.html` for React Router.

Keep the scikit-learn version in `requirements.txt` identical to the one used for training.
